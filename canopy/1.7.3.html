Advanced

Scrollytelling is expensive to build and easy to misuse. Before writing a line of code, the real question is whether the content actually needs the reader's scroll position to unfold — or whether it's being used because it looks impressive, not because it serves the story.

When Interactive Format Adds Value vs. Decoration

Decoration

A simple linear narrative gets chopped into scroll-triggered fragments purely for visual novelty — the reader could get the same understanding from a normal article, just with more friction to read it.

Genuine Value

A story with a genuinely spatial or sequential dimension — how deforestation spread across a map over a decade, how a river's course shifted — where seeing the change unfold as you scroll or interact conveys something static text and images can't.

A useful test: could this story be told just as well as a well-structured long-form article with embedded charts? If yes, the interactive format is probably decoration. If the sequence or interactivity itself is doing narrative work a static article couldn't, it's earning its place.

Pacing Scroll-Triggered Reveals

Each scroll-triggered reveal should mirror the pace at which a reader can actually absorb new information — not the pace that looks most dramatic in a demo. Revealing three data points in rapid succession without pause tends to overwhelm rather than build understanding; spacing reveals to match a natural reading rhythm respects the reader's attention.

Structuring a Scrollytelling Outline

Hook

A striking opening moment or visual that earns the scroll — before any data appears.

Escalating Data Reveals

Each reveal should build on the last, increasing in specificity or stakes rather than repeating the same kind of point.

Human Anchor

At least one grounding character moment partway through, so the piece doesn't read as pure abstraction.

Resolution

A closing takeaway that gives the reader something to do with everything they've just scrolled through.

Production Basics

Technically, most of what you need is a single HTML file with scroll-position detection (an Intersection Observer watching each section as it enters the viewport) triggering CSS transitions or class changes — the same underlying pattern used throughout this toolkit's own modules. Keep the file self-contained, test on an actual phone rather than only a desktop browser, and always build in a way for the content to be understood even if the animation fails to load.

"If turning off the animation would make the story unreadable, the story was relying on the effect instead of the reporting."
